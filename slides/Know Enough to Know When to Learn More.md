# Know Enough to Know When to Learn More

Technology တစ်ခုကို “သိတယ် / မသိဘူး” ဆိုပြီး နှစ်မျိုးတည်း ခွဲထားရင် learning ကို မလိုအပ်ဘဲ အကြီးကြီးလုပ်မိနိုင်ပါတယ်။ ဒီ slide က knowledge ကို အဆင့် ၆ ဆင့်နဲ့ ကြည့်ထားပါတယ်။

1. **Never heard of it** — နာမည်တောင် မကြားဖူးသေးတာ
2. **Know it exists** — ဒီလို tool/category ရှိတယ်ဆိုတာ သိတာ
3. **Understand the problem it solves** — ဘာ problem ကို ဖြေရှင်းတာလဲ သိတာ
4. **Know when to use it** — ဘယ်အခြေအနေမှာ သုံးသင့်တယ်/မသုံးသင့်ဘူး သိတာ
5. **Can use it** — ကိုယ်တိုင် အသုံးချနိုင်တာ
6. **Deep expertise** — အတွင်းပိုင်းအထိ နက်နက်ရှိုင်းရှိုင်း ကျွမ်းကျင်တာ

## အရေးကြီးဆုံးအဆင့်

Slide က **Rung 3 is where most people live** လို့ ပြောထားပါတယ်။ လူတိုင်း tool တိုင်းကို Level 5 သို့မဟုတ် Level 6 အထိ သွားစရာမလိုပါဘူး။

Level 3 လောက်နဲ့တင် job posting တစ်ခုဖတ်တဲ့အခါ technology name တွေကြောင့် မကြောက်တော့ဘဲ၊ conversation ထဲမှာ ဘာအကြောင်းပြောနေလဲ နားလည်နိုင်ပြီး လိုလာတဲ့အခါ ဘယ်နေရာကို ပြန်သွားလေ့လာရမလဲ သိနိုင်ပါတယ်။

## Learning ကို အလုပ်မဖြစ်အောင် မလုပ်မိဖို့

Tool တစ်ခုတွေ့တိုင်း “ဒါကိုလည်း လေ့လာရမယ်” ဆိုပြီး course တစ်ခု၊ book တစ်ခု၊ roadmap တစ်ခု ထပ်မစပါနဲ့။ တကယ်လိုလာတဲ့အချိန်မှာ rung တစ်ဆင့်ချင်း တက်သွားလို့ရပါတယ်။

##

Technology အားလုံးကို တူညီတဲ့အနက်နဲ့ လေ့လာဖို့ မလိုပါဘူး။ နေ့တိုင်းသုံးရမယ့် tool တစ်ခု၊ တစ်နှစ်မှာတစ်ခါလောက်သာ တွေ့ရမယ့် tool တစ်ခုနဲ့ ကိုယ့်အလုပ်နဲ့ မဆိုင်သလောက်ဖြစ်နေတဲ့ tool တစ်ခုကို အချိန်တူတူ ပေးနေတာက အကျိုးရှိမှာမဟုတ်ပါဘူး။

ဒီနေရာမှာ breadth က အရေးကြီးပါတယ်။ Technology တစ်ခုရဲ့ နာမည်နဲ့ အကြမ်းဖျင်း role ကို သိထားရုံနဲ့ ကိုယ်မသိသေးတဲ့အချိန် ဘယ်နေရာကို သွားရှာရမလဲ သိလာပါတယ်။ Distributed tracing ဆိုတာ request တစ်ခုကို service တော်တော်များများဖြတ်သွားတဲ့အခါ လိုက်ကြည့်တာလို့ သိထားရင် အဲဒီကနေ documentation ကို ဆက်ရှာနိုင်ပါတယ်။

တကယ်နက်နက်လေ့လာဖို့ကတော့ အကြောင်းပြချက်ရှိလာမှ လုပ်တာပိုကောင်းပါတယ်။ ကိုယ့်အလုပ်မှာ အဲဒီ concept က ထပ်ခါထပ်ခါပေါ်လာတာ၊ တူညီတဲ့ problem ကို ခဏခဏ debug လုပ်နေရတာ၊ ဒါမှမဟုတ် architecture decision တစ်ခုကို အဲဒီ technology နဲ့ ချရတော့မယ့်အချိန်တွေက deeper learning လုပ်ဖို့ အချိန်ရောက်ပြီဆိုတဲ့ signal တွေပါ။

ဒီလိုဆို learning က “အကုန်သင်ပြီးမှ project လုပ်မယ်” မဟုတ်တော့ဘဲ **သိထား → problem တွေ့ → လိုတာရှာ → သုံးကြည့် → ပိုနက်နက်နားလည်** ဆိုတဲ့ cycle ဖြစ်လာပါတယ်။

# The Software World Is Bigger Day by Day

> “There is a lot more out there than what I currently use.”

နေ့တိုင်းကိုယ်သုံးနေတဲ့ technology တွေက software world တစ်ခုလုံးမဟုတ်ပါဘူး။ ဒီ slide မှာ ecosystem ကို အပိုင်းခြောက်ပိုင်းခွဲပြီး ကြည့်ထားပါတယ်။

### Frontend / Interface
React, Vue, Svelte လို web technologies တွေ၊ Swift/Kotlin/Flutter လို application UI technologies တွေရှိပါတယ်။ CSS ကိုလည်း UI အလှဆင်တာလောက်မဟုတ်ဘဲ ကိုယ်ပိုင် language တစ်ခုအနေနဲ့ သိထားဖို့လိုပါတယ်။

### Systems / Backend
Go, Rust, Elixir, Java လို languages တွေရှိသလို REST, gRPC, GraphQL လို systems တွေပြောဆိုဖို့ နည်းလမ်းတွေရှိပါတယ်။ Auth, sessions, OAuth လို concepts တွေက application တွေရဲ့ နောက်ကွယ်မှာ အမြဲတွေ့ရတတ်ပါတယ်။

### Data / Intelligence
Postgres, SQLite, DuckDB လို databases တွေကနေ Pandas, PyTorch လို tools တွေအထိ ရှိပါတယ်။ Embeddings နဲ့ vector search လို concept တွေကလည်း data/AI ecosystem ရဲ့ အစိတ်အပိုင်းတွေပါ။

### Platform
Docker, Kubernetes, AWS, GCP, Terraform, CI/CD, observability စတာတွေက application ကို run, deploy, scale, monitor လုပ်တဲ့ဘက်မှာ ပါလာပါတယ်။

### Foundation
Linux, networking, TLS, Git, code review, testing, profiling စတာတွေက framework တစ်ခုထက် ပိုအခြေခံကျတဲ့ knowledge တွေပါ။

### Workflow
Editor, terminal, GitHub, feature flags, rollouts, documentation စတာတွေက developer တစ်ယောက်ရဲ့ နေ့စဉ်လုပ်ငန်းစဉ်ထဲက အစိတ်အပိုင်းတွေပါ။

## အဓိက takeaway

**You don't need to know all of this. You need to know it exists.**

“သိတယ်” ဆိုတာ tutorial အကုန်ဖတ်ပြီးသွားတာ မဟုတ်ပါဘူး။ “ဒီလို problem ရှိရင် ဒီလို tool category တစ်ခု ရှိနိုင်တယ်” လို့ ချိတ်ဆက်စဉ်းစားနိုင်တာကို ဆိုလိုပါတယ်။

##

Software ecosystem ကို ကြည့်တဲ့အခါ framework, database, cloud, DevOps, AI ဆိုပြီး သီးခြားအကွက်တွေလို မြင်ရလွယ်ပါတယ်။ တကယ်တမ်းမှာတော့ အဲဒီအရာတွေက တစ်ခုနဲ့တစ်ခု ချိတ်ဆက်နေပါတယ်။ User တစ်ယောက်က button တစ်ခုနှိပ်လိုက်တာက UI ကနေ API ကိုသွား၊ authentication ဖြတ်၊ application logic ထဲဝင်၊ database ကိုဖတ်၊ လိုအပ်ရင် cache သုံး၊ background job တစ်ခုတင်၊ ပြီးရင် monitoring နဲ့ deployment အထိ ဆက်သွားနိုင်ပါတယ်။

ဒါကြောင့် ကိုယ်က frontend developer ဖြစ်လို့ backend ကို မသိလို့ရတယ်ဆိုတာမျိုး မဟုတ်ပါဘူး။ Backend developer ဖြစ်လို့ UI ကို ကျွမ်းကျင်ဖို့လည်း မလိုပါဘူး။ ကိုယ့်အလုပ်နဲ့ ဆက်စပ်နေတဲ့ အနီးအနားက layer တွေ ဘာလုပ်ပေးတယ်ဆိုတာ သိထားရုံနဲ့တင် decision တွေ ပိုကောင်းလာပါတယ်။ Specialization က အရေးကြီးပေမယ့် isolation ကတော့ အားသာချက်မဟုတ်ပါဘူး။

Technology တစ်ခုချင်းစီကို product name နဲ့ မစလေ့လာဘဲ concept နဲ့ စလေ့လာတာ ပိုခံပါတယ်။ “Data ကို ဘယ်မှာသိမ်းမလဲ”, “Request နှေးလာရင် ဘာလုပ်မလဲ”, “Service တစ်ခုကျသွားရင် ဘာဖြစ်မလဲ”, “System ကို ဘယ်လိုစောင့်ကြည့်မလဲ” ဆိုတဲ့မေးခွန်းတွေက product တွေပြောင်းသွားရင်တောင် မပြောင်းပါဘူး။

ဒီ map ကို တစ်ခါတည်း အပြည့်ဆွဲဖို့ မလိုပါဘူး။ ဒီနေ့ Kubernetes ဆိုတာ ရှိတယ်လို့ပဲ သိနိုင်ပါတယ်။ နောက်တစ်ချိန်မှာ orchestration ဆိုတာ ဘာလဲသိလာမယ်။ အဲဒီနောက် scheduling, service discovery, networking, health check တွေအထိ တဖြည်းဖြည်း zoom in လုပ်သွားနိုင်ပါတယ်။ Experience က ဘယ်နေရာကို ပိုနက်နက်လေ့လာသင့်လဲဆိုတာ ပြောပေးပါလိမ့်မယ်။
